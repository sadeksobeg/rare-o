# مسارات المستخدمين — RARE OUD

5–8 مسارات لكل دور، مبنية على السلوك التجاري الفعلي الموثَّق في `docs/ui-planning/plan/` والمُتحقَّق
منه بالتصفح الحي في جلسات سابقة (`PROJECT_AUDIT.md`). كل مسار: الهدف → الخطوات → الصفحات
(معرّفات IA.md) → حالة نجاح.

## زائر (6 مسارات)

1. **اكتشاف واستكشاف** — الرئيسية → تصفّح المجموعات → الكتالوج مُصفّى حسب نوع/سعر → منتج.
   (SF-01 → SF-02 → SF-03)
2. **طلب قطعة واحدة** — منتج → "أضف إلى قائمة الطلب" → قائمة الطلب → الطلب (بيانات تواصل) →
   فتح واتساب برسالة معدّة. (SF-03 → SF-04 → SF-05 → واتساب خارجي). **لا دفع في أي خطوة.**
3. **السعر عند الطلب** — منتج بلا سعر معلن → شارة "السعر عند الطلب" بدل رقم → نفس مسار
   الطلب دون سعر ظاهر. (D6)
4. **تصفّح عرض مُختار** — الرئيسية أو رابط مباشر → صفحة عرض → إضافة للطلب أو تواصل مباشر.
   (SF-06 → SF-07)
5. **بحث بالطلب الفارغ** — كتالوج بفلاتر لا تُرجع نتائج → حالة فارغة برسالة + إجراء مسح
   الفلاتر (لا "0 نتيجة" مجرّدة).
6. **الهاتف الضعيف/غير متصل** — طلب على اتصال بطيء → تدهور لطيف (Lite motion، شريط انقطاع
   اتصال دون فقد مدخلات النموذج).

## تاجر (7 مسارات)

1. **الدخول الأول** — بريد/كلمة مرور أرسلتهما الإدارة → `/trader/login` → الرئيسية.
   (TR-01 → TR-02)
2. **اقتراح صفقة على قطعة من الكتالوج** — الرئيسية → "اقترح صفقة" → معالج (اختيار منتج،
   سعر مقترح، كمية، ملاحظات) → إرسال → الصفقة في "صفقاتي" بحالة `proposed`.
   (TR-02 → TR-04 → TR-03/TR-05)
3. **اقتراح صفقة خارج الكتالوج** — نفس المعالج، وضع "غير مرتبط بمنتج" → عنوان حر بدل اختيار
   منتج. (قاعدة عمل: `dealKind=non_catalog` لا يملك `productId` — مفحوصة سيرفرياً)
4. **التفاوض على صفقة** — تفاصيل صفقة بحالة `negotiating` → رد الإدارة بعرض مقابل → التاجر
   يقبل/يرفض/يُعاود العرض → تُغلق أو تُقبَل. (TR-05)
5. **طلب جملة بالسعر المطلوب من الإدارة** — بوابة الجملة → اختيار قطع وكميات
   (`wholesaleEligible` فقط) → إرسال وضع `request_quote` → انتظار عرض سعر الإدارة → قبول/رفض.
   (TR-06 → TR-08)
6. **طلب جملة بسعر مقترح من التاجر** — نفس البوابة، وضع `propose_price` → إدخال سعر لكل سطر
   إلزامياً. (TR-06)
7. **متابعة الإشعارات** — شارة إشعار في الرأس → `/trader/notifications` → قراءة/تعليم الكل
   كمقروء → فتح السجل المرتبط.

## إدارة (8 مسارات)

1. **الصباح التشغيلي** — الدخول (+2FA إن مفعَّل) → لوحة التحكم: KPI + طابور الإجراءات
   المطلوبة + آخر نشاط. (AD-01 → AD-02)
2. **معالجة طلب تجزئة جديد** — طابور الإجراءات → فتح طلب → مراجعة القطع وبيانات العميل →
   تحويل الحالة (جديد→متابعة→فُتح→مكتمل) مع ملاحظة. (AD-02 → AD-04)
3. **الرد على صفقة تاجر** — طابور أو `/admin/deals` → تفاصيل صفقة `proposed`/`negotiating` →
   قبول/رفض/عرض مقابل. **قاعدة منع تعارض:** صفقتان على نفس المنتج من تاجرين تُحجَب تلقائياً
   حتى تُغلَق إحداهما (`DEAL_PRODUCT_CONFLICT`، تحذير إداري لا منع صارم).
4. **تسعير طلب جملة** — `/admin/wholesale/[id]` بوضع `request_quote` → إدخال سعر/عملة لكل
   سطر → إرسال العرض → التاجر يقبل/يرفض من بوابته.
5. **إدارة المنتجات** — `/admin/products` → منتج جديد (صور، فيديو، مواصفات عود، سعر أو
   "بلا سعر معلن") → نشر. (AD-07)
6. **صندوق واتساب (محلي، غير متصل بخط حقيقي)** — `/admin/inbox` → محادثة → رد نصي (إن
   فُعِّل الإرسال) → ربط المحادثة بسجل تجزئة/صفقة/جملة قائم.
7. **إدارة حسابات التجّار** — `/admin/traders` → إنشاء حساب تاجر (بريد + كلمة مرور لمرة
   واحدة) أو تعطيله. لا تسجيل ذاتي للتاجر بديل عن هذا المسار.
8. **تدقيق نشاط عميل** — `/admin/customers/[id]` → تاريخ الطلبات + روابط محادثات واتساب
   المرتبطة.

## ملاحظة حول الوساطة والتوريد المباشر
مسار مقترح (غير مُنفَّذ، بانتظار قرار مالك — انظر `GAPS.md`): تاجر يرسل وجهة/سلعة رآها ←
الإدارة تعاين وتقرر ← عند القبول تُنشأ "وحدة وساطة" بعمولة 1–2% ← شحن وتتبّع. لا يُضاف هنا
كمسار معتمَد لأنه خارج الملحق S حتى الآن.
