## 2. تفصيل البنود

### 7.1 — تشفير وتخزين آمن (مُسلَّم)

ما يشمله العقد: *«تشفير البيانات الحساسة وتخزينها بشكل آمن»*.

| طبقة | التنفيذ |
|------|---------|
| كلمات المرور | bcrypt (تكلفة 12) لحسابات الإدارة والتجّار |
| الجلسات | JWT موقَّع + كوكيز HttpOnly / SameSite / Secure في الإنتاج |
| التحقق بخطوتين | أسرار TOTP مشفّرة AES-256-GCM في قاعدة البيانات |
| جلسة واتساب على القرص | AES-256-GCM عند ضبط `WHATSAPP_AUTH_KEY` (موصى به في الإنتاج) |
| النقل | HTTPS على الموقع الحي + HSTS |
| الأسرار | متغيرات بيئة فقط — غير مُلتزَمة في المستودع |

**تحقق آلي:** `npm run test:security-storage`  
**مرجع تقني:** `docs/security/ENCRYPTION-AND-STORAGE.md` · `docs/security/ASVS-L2.md`

**صراحة النطاق:** تشفير كل حقول الأسماء/الهواتف داخل Postgres حقلًا-حقلًا **غير مطلوب** في بند 7.1 من العقد، وهو مُعلَّم خارج النطاق في قائمة ASVS.

### 7.2 — نسخ احتياطي يومي (مُسلَّم)

- سكربت يومي: قاعدة البيانات + الوسائط + مجلد جلسة واتساب.
- استبقاء قابل للضبط + تنبيه مساحة القرص على الخادم.
- تمرين استعادة موثّق (جداول + بصمات ملفات).

**مرجع:** `docs/handover/RUNBOOKS/backup-restore.md`

### 7.3 — ضمان الجودة والاختبار (مُسلَّم)

- انحدار أسبوعي للمسارات التجارية (تجزئة / صفقات / جملة).
- فحوص أمان (جلسات، صلاحيات تاجر، واتساب الآمن، 2FA).
- فحوص وصول axe وفحوص بناء/أنواع ضمن مسار التسليم.
- معنى البند في العقد: *«اختبار شامل لكل الوظائف قبل الإطلاق»* — اجتياز وظيفي، وليس إعادة قياس أداء Lighthouse للمتجر كشرط إغلاق منفصل (يُتتبَّع تحت بنود الواجهة عند الحاجة).

### 7.4 — النشر ودعم الإطلاق (مُسلَّم)

- المنصة منشورة على VPS مستقل ومعزول عن خدمات أخرى على نفس الخادم.
- حزمة نشر (Docker / nginx) + دفاتر تشغيل.
- اختبار دخان على المسارات الحرجة بعد النشر.
- دعم أيام الإطلاق: عبر قناة التشغيل المتفق عليها مع المالك (عملية تشغيل، ليست ميزة برمجية).

### 7.5 — النطاق وشهادة SSL (مُسلَّم)

- `https://rareoud.com` متاح للعامة.
- شهادة Let’s Encrypt فعّالة مع إعادة توجيه HTTP→HTTPS.
