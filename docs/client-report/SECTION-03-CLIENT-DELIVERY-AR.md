## 2. وصف الواجهات والسلوك

### 3.1 — تسجيل وإعداد التجّار
- الإدارة: `/admin/traders` — إنشاء حساب (بريد، كلمة مرور، اسم، شركة، هاتف) وتفعيل/تعطيل.
- التاجر: `/trader/login` فقط — **لا يوجد تسجيل ذاتي عام** (قرار نطاق صريح).
- بعد الدخول: هيكل بوابة (هيدر داكن، تبويبات، قائمة جوال سفلية).

### 3.2 — متابعة حالة الصفقات + التفضيلات
- قائمة `/trader/deals` مع تبويبات: الكل / بانتظارك / تفاوض / مغلقة.
- تفاصيل `/trader/deals/[id]` مع خط تفاوض وشريحة حالة.
- الصفحة الرئيسية تعرض ما ينتظر إجراء التاجر.
- **جديد:** في `/trader/profile` نموذج تفضيلات (فئات اهتمام + ملاحظات) للإدارة فقط.

### 3.3 — رؤية الطلبات الخاصة فقط
- كل استعلامات الصفقات والجملة مقيّدة بـ `traderId` من الجلسة.
- اختبارات انحدار IDOR موجودة في سكربتات الأسبوع 3.

### 3.4 — مركز الإشعارات
- مسار جديد: `/trader/notifications` (مركز الحالة).
- جرس في هيدر البوابة مع عدّاد غير المقروء.
- إشعار عند: رد/قبول/إغلاق صفقة من الإدارة، عرض سعر جملة، تغيير حالة جملة.
- تعليم مقروء / تعليم الكل.

### 3.5 — عرض موحّد للمتسوق
- `/offers` و`/offers/[slug]` — عروض `PublicCuratedOffer` المنشورة فقط.
- لا يظهر اسم التاجر أو مصدر الصفقة في المتجر.
- تجّار مسجّلون يرون نفس العروض عبر `/trader/offers`.

### 3.6 — منطق تعارض الصفقات
- عند اقتراح صفقة كتالوج على منتج عليه صفقة نشطة/مقبولة لتاجر آخر → رفض مع رسالة واضحة.
- عند قبول الإدارة لصفقة تتعارض مع تاجر آخر على نفس المنتج → رفض القبول.
- الحالات المتعارضة: `proposed` · `negotiating` · `accepted`.

### 3.7 — اقتراح صفقات/عروض من التاجر
- معالج `/trader/deals/new` (كتالوج / غير كتالوج) → حالة `proposed`.
- لا يظهر شيء في المتجر تلقائياً.
- الإدارة تنشئ عرضاً عاماً يدوياً؛ **إن رُبط العرض بصفقة** فلا يُنشر إلا إذا كانت الصفقة `accepted`.

## 3. مسارات تجريبية سريعة

1. إدارة → إنشاء تاجر → دخول `/trader/login`.  
2. تاجر → صفقة جديدة على منتج → إن وُجدت صفقة نشطة لتاجر آخر تُرفض.  
3. إدارة → قبول/عرض مقابل → يظهر إشعار عند التاجر (الجرس).  
4. تاجر → تفضيلات في الملف الشخصي → حفظ.  
5. إدارة → محاولة نشر عرض مربوط بصفقة غير مقبولة → تُرفض.  
6. متجر `/offers` — عرض منشور بلا ذكر تاجر.

---

## 4. ملاحظات صريحة للعميل

1. إنشاء التجّار من الإدارة فقط (لا بوابة تسجيل عامة).  
2. حالات الصفقة في النظام: مقترحة / تفاوض / مقبولة / مغلقة (مرادف عملي لـ قيد المراجعة / معتمدة / مرفوضة).  
3. «الطلبات» عند التاجر = صفقات + جملة — طلبات تجزئة الزوار تبقى في الإدارة.  
4. الإشعارات داخل البوابة (ليست بريد/واتساب للتاجر في هذا القسم).
