## الجزء B — تعريف الإنجاز العالمي (Definition of Done)

كل شاشة، بلا استثناء، يجب أن تحقق كل البنود. المنفّذ يملأ هذه القائمة لكل شاشة في `docs/ui-planning/DOD/{screen-id}.md`.

### B1. التصميم البصري

- [ ] **تسلسل واضح:** نقطة تركيز واحدة وإجراء أساسي واحد بارز. اختبار التمويه: لقطة مصغّرة ومموّهة تُظهر الأهم فوراً.
- [ ] **عمق:** طبقات وضوء وملمس. لا ألواح رمادية مسطحة، ولا عناصر تحكم افتراضية بلا تخصيص.
- [ ] **حضور العلامة:** الشعار الحقيقي ظاهر في المكان المناسب، والهوية (الأسود، الكريمي، البنفسجي، لمسة الكهرمان) واضحة دون ضجيج.
- [ ] **صور حقيقية** حيث تخدم الشاشة (بطاقات، أبطال، حالات فارغة، صفحات الدخول)، مسجّلة في `ASSETS.md`.
- [ ] **مقياس خط واحد** من الثيم، **أيقونات** Lucide 1.5 بمقاسات 16/20/24 فقط، **شبكة 8px** للمسافات. صفر قيم عشوائية (دليل grep).
- [ ] **مطابقة اللاب:** إن وُجدت الشاشة في اللاب، لقطتا مقارنة 375 و1440 بالعربية، والتطبيق مساوٍ أو أفضل.
- [ ] **مقارنة مرجعية:** ثلاث شاشات من منتجات عالمية من نفس النوع، والفجوات مغلقة.

### B2. الحركة

| المنطقة | الطابع | الحدود |
|---|---|---|
| الدخول | سينمائي مرة واحدة | مقدمة ≤ 2.5 ث، الشعار ثلاثي الأبعاد كسول مع بديل ثابت |
| الإدارة | سريع ودقيق وحي | حالات الواجهة ≤ 250ms، رسوم البيانات ≤ 900ms، نبض للبيانات الجديدة |
| التاجر | دافئ ومكافئ | انتقالات المعالج، احتفال نجاح بسيط، نبض "بانتظارك" |
| المتجر | قصصي سينمائي | تمرير مُوجَّه، كشف نصوص، تكبير صور، بلا scroll-jacking |

- [ ] كل حركة لها سبب (توجيه، تأكيد، تغيير، هوية).
- [ ] transform/opacity فقط حيث أمكن، 60 إطاراً.
- [ ] reduced-motion وSave-Data متحقق منهما حياً (Playwright).
- [ ] العدّادات والرسوم تعمل بعد التنقل للخلف والأمام وإعادة التحميل.

### B3. الوظائف

- [ ] **بيانات حقيقية فقط.** صفر بيانات تجريبية في التطبيق الحقيقي.
- [ ] **كل الحالات مصمَّمة:** تحميل (هيكل مطابق للمحتوى)، فارغ (مع إجراء)، لا نتائج (مسح الفلاتر)، خطأ (مع إعادة المحاولة)، فشل جزئي (قسم واحد يفشل لا يُسقط الصفحة)، غير متصل، نجاح.
- [ ] **النماذج:** تحقق عند مغادرة الحقل، ملخص أخطاء عند الإرسال مع نقل التركيز إليه، حالة إرسال، منع الإرسال المزدوج، عدم فقدان البيانات عند الفشل، تحذير التغييرات غير المحفوظة.
- [ ] **الإجراءات:** تأكيد لكل إجراء مدمّر يسمّي النتيجة، تنبيه نجاح، تراجع (Undo) للإجراءات القابلة للعكس حيث يصلح.
- [ ] **القوائم:** بحث وفلترة وترتيب **محفوظة في الرابط**، ترقيم صفحات، أعداد مطابقة للقوائم (اختبار آلي).
- [ ] **الصلاحيات من الخادم:** كل مسار وكل server action يتحقق من الدور والملكية. اختبار IDOR لكل صفحة تفاصيل.
- [ ] **سجل الأحداث:** كل تغيير حالة أو صلاحية أو كلمة مرور يُسجَّل.
- [ ] **اختصارات لوحة المفاتيح** للإجراءات المتكررة في الإدارة، وظاهرة في لوحة الأوامر.

### B4. اللغة والاتجاه

- [ ] كل نص من القاموس (`check-i18n` يمر، وgrep يثبت صفر نصوص داخل JSX وصفر ثلاثيات `ar ? :`).
- [ ] صيغ الجمع العربية الست عبر `Intl.PluralRules`.
- [ ] أرقام لاتينية، تواريخ بتوقيت دمشق، أسماء وأرقام لاتينية داخل `<bdi>`.
- [ ] تصميم عربي أولاً، والإنجليزية مرآة متحقق منها. خصائص منطقية فقط.

### B5. الوصولية

- [ ] WCAG 2.2 AA، تباين النص ≥ 4.5:1 (والهدف 7:1 لنص الجسم).
- [ ] axe صفر مخالفات على خادم مستقر.
- [ ] مسار كامل بلوحة المفاتيح، تركيز ظاهر، Escape يغلق والتركيز يعود.
- [ ] أهداف لمس ≥ 44px، معالم (landmarks)، عنوان h1 واحد، تسميات لكل عنصر أيقوني.

### B6. الأداء

- [ ] JavaScript الأول لكل مسار ضمن الميزانية (تقرير الحزمة).
- [ ] المكتبات الثقيلة (Three.js، الرسوم، لوحة الأوامر) محمَّلة عند الحاجة.
- [ ] صور عبر `next/image` بأبعاد محجوزة. CLS ≤ 0.1.
- [ ] المتجر: LCP ≤ 2.5 ث على 4G بطيء للهاتف.

### B7. الدليل المطلوب لكل شاشة

لقطات (375 / 768 / 1440 × عربي / إنجليزي)، فيديو للتدفق الرئيسي، نتائج axe، نتيجة اختبار الصلاحيات، مقارنة اللاب، ملف DOD مكتمل. كلها في `artifacts/` (مستثنى من git) مع ملخص نصي في `docs/ui-planning/evidence/{phase}.md`.

## الجزء C — كتالوج الشاشات

كل شاشة لها معرّف. "مرجع اللاب" يعني أن التصميم المعتمد موجود في `design-lab/` ويجب مطابقته أو تجاوزه. المسارات مأخوذة من الخطط السابقة، والمنفّذ يتحقق منها في المرحلة 2 ويبلغ عن أي اختلاف.

### C1. الدخول والحسابات (المرحلة 3)

**AUTH-01 دخول الإدارة** `/admin/login` — مرجع اللاب: `/login`
- مرئي: شاشة مقسومة؛ مشهد العلامة بالشعار ثلاثي الأبعاد مع ضوء وجسيمات، وبطاقة نموذج بعمق. نص ترحيبي احترافي.
- وظيفي: بريد وكلمة مرور، إظهار/إخفاء، تحذير Caps Lock، حقل TOTP أو رمز استرداد عند تفعيل 2FA (موجود في التطبيق)، رسائل خطأ عامة، تحديد المحاولات مع رسالة واضحة، returnTo بعد الدخول.
- حركة: مقدمة مرة واحدة، اهتزاز خطأ مخفّف، انتقال للوحة التحكم.
- قبول: لا وميض للواجهة القديمة، يعمل مع مدير كلمات المرور.

**AUTH-02 دخول التاجر** `/trader/login` — مرجع اللاب: `/login` (تبويب التاجر)
- كما AUTH-01 بنسخة دافئة، ورابط "اطلب حساب تاجر" يفتح واتساب برسالة جاهزة.

**AUTH-03 نسيت كلمة المرور** — شاشة تشرح أن الحسابات تُدار من الإدارة، مع زر تواصل واتساب. لا إعادة تعيين ذاتية بالبريد إلا إذا كان النظام يدعمها (يبلَّغ عنه).

**AUTH-04 تغيير كلمة المرور الإجباري** — مرجع اللاب: `/force-password-change`
- يُبنى بصرياً فوق منطق المرحلة 1. مؤشر قوة، قائمة شروط تتحقق مباشرة، رسالة سبب واضحة ("أُعيد تعيين كلمة مرورك. اختر كلمة جديدة للمتابعة").

**AUTH-05 التحقق بخطوتين** — شاشة إدخال الرمز، ورموز الاسترداد، ورسالة "تذكّر هذا الجهاز" إن كانت مدعومة.

**AUTH-06 صفحات النظام** — 403 (بزر الذهاب لبوابتك)، انتهاء الجلسة، 404، خطأ عام، غير متصل. كلها بهوية كاملة وصورة أو حركة خفيفة، ليست نصاً على خلفية فارغة.

**AUTH-07 حسابي (للأدوار كلها)** — مرجع اللاب: `/admin/profile`
- مرئي: غلاف بصورة، صورة شخصية قابلة للرفع والقص، تبويبات.
- وظيفي: البيانات الشخصية، اللغة، المظهر، تغيير كلمة المرور بنفس السياسة، تفعيل/تعطيل 2FA، الجلسات النشطة مع "تسجيل الخروج من الأجهزة الأخرى".

### C2. الإدارة — النواة (المرحلة 4)

**ADM-00 غلاف الإدارة** — مرجع اللاب: غلاف `/admin`
- شريط جانبي داكن بالشعار، مجموعات (التشغيل، الكتالوج، الأشخاص، النظام)، شارات أعداد حية، طي إلى أيقونات مع تلميحات، درج على الهاتف، `<nav>` موسوم.
- شريط علوي: ترحيب بالاسم حسب الوقت، بحث عام (يفتح لوحة الأوامر)، حالة واتساب، الإشعارات، اللغة، قائمة المستخدم بالصورة.
- لوحة أوامر Ctrl/⌘+K: تنقل، إجراءات، بحث في السجلات (طلبات، صفقات، تجار، منتجات، وساطة).

**ADM-01 لوحة التحكم** `/admin` — مرجع اللاب: `/admin`
- مرئي: رأس متدرج بالشعار والترحيب والتاريخ وسطر الحالة الحية، مؤشرات بأرقام متحركة واتجاهات، مخطط مساحي للطلبات عبر الزمن، مخطط دائري لتوزيع المجالات الأربعة، طابور "بانتظار إجراءك" بأزرار سريعة وشارات عمر، تغذية نشاط، بطاقة واتساب حية، ويدجت الوساطة، قائمة إنشاء سريع.
- وظيفي: كل رقم يطابق قائمته المفلترة (اختبار)، الضغط على أي مؤشر يفتح القائمة المفلترة، الطابور مرتب حسب العمر، تحديث دوري خفيف.
- حالات: صفر بيانات يعرض لوحة "أول استخدام" بخطوات بدء جميلة، لا صفحة فارغة.

**ADM-02 التجار** `/admin/traders` + تفاصيل — مرجع اللاب: `/admin/traders`
- قائمة بصور/أحرف أولى، حالة، آخر دخول، أعداد الصفقات والجملة والوساطة. ملف تاجر شامل: بيانات، خريطة نشاط، سجل الصفقات والجملة والوساطة، ملاحظات إدارية.
- إنشاء، تعديل، تعطيل/تفعيل بتأكيد يشرح النتيجة، إعادة تعيين كلمة المرور (عرض مرة واحدة + تغيير إجباري).

**ADM-03 الفريق والأمان** `/admin/team` — مرجع اللاب: `/admin/team` و`/admin/audit-log`
- تبويب الفريق: الأعضاء، الأدوار (مالك/مدير/موظف)، مصفوفة صلاحيات، دعوة/إنشاء، تعطيل، إعادة تعيين.
- تبويب سجل الأمان: من فعل ماذا ومتى، فلترة حسب الشخص والنوع والتاريخ، تصدير CSV.

**ADM-04 العملاء** `/admin/customers` — مرجع اللاب: `/admin/customers`
- قائمة وبحث، لوحة جانبية للتفاصيل: بيانات التواصل، سجل الطلبات، المحادثات المرتبطة، ملاحظات ووسوم إن دعمها المخطط.

**ADM-05 الوساطة** `/admin/brokerage` + `/[id]` — مرجع اللاب: شاشات الوساطة
- لوحة Kanban وجدول، فلاتر (تاجر، مدينة، عمر)، شارات تأخر.
- التفاصيل: بطاقة "أين نحن الآن" ومسار المراحل (إضافات التطبيق الحالية تبقى)، معالج تقرير المعاينة (صور عبر المسار المحمي، تقييم، قائمة فحص، حكم)، منشئ العرض (قيمة البضاعة، شريط العمولة 1–2% بالمبلغ الحي، الشحن، الصلاحية)، الشراء والشحن، الخط الزمني، المحادثة المرتبطة.

### C3. الإدارة — التشغيل (المرحلة 5)

لا توجد في اللاب. تُصمم وتُبنى مباشرة وفق VISION.md القسم 5.3 إلى 5.4.

**OPS-01 صندوق واتساب** `/admin/inbox`
- ثلاث لوحات قابلة لتغيير الحجم على الحاسوب، شاشات متتالية على الهاتف مع حماية لوحة المفاتيح.
- قائمة المحادثات: صورة/حرف، معاينة، وقت، توهج غير مقروء، شارة السجل المرتبط، تبويبات (الكل، غير مقروءة، مرتبطة، غير مرتبطة)، بحث.
- المحادثة: فقاعات مجمّعة، فواصل أيام، علامات التسليم، فشل مع إعادة محاولة واحدة لكل ضغطة، رسائل غير نصية بإطار معاينة.

**OPS-02 طلبات التجزئة** `/admin/requests` + `/[id]`
