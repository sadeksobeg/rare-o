# RARE OUD — دليل الاستخدام والاختبار حالة بحالة

مبني على الكود الفعلي (المسارات، الإجراءات، وسلاسل الحالات). لكل حالة: **الخطوات ← النتيجة المتوقعة ← أين تتأكد**.
علّم ☐ → ✅ أثناء المشي. أي نتيجة مخالفة للمتوقع سجّلها مع لقطة شاشة.

## 0) قواعد قبل البدء (مهم)
- جهّز **حسابَي تاجر تجريبيين** (A و B) وزبوناً وهمياً. لا تستخدم بيانات عملاء حقيقيين.
- **واتساب:** الإرسال حقيقي على الإنتاج. أرسل فقط لرقمك الشخصي. لا تختبر الرسائل على أرقام عملاء.
- بعد كل حالة بيانات تجريبية: احذفها/ألغِها أو ضع عليها وسم «اختبار» في الملاحظات.
- اختبر كل حالة **بالعربية ثم الإنجليزية** (`/en/...`)، وعلى **الجوال (390)** و**سطح المكتب**، **فاتح وداكن**.
- مسارات `/dev/*` يجب أن تعطي 404 على الإنتاج.

## 7) الوساطة (Brokerage)
مسار الإدارة: `SUBMITTED → NEEDS_INFO/AWAITING_PAYMENT → PAYMENT_CONFIRMED → ACCEPTED → INSPECTION_SCHEDULED → INSPECTED → QUOTE_SENT/PURCHASED → APPROVED → PURCHASED → SHIPPED → DELIVERED → CLOSED`. التاجر: يردّ على العرض (APPROVED/REJECTED)، يلغي، يعيد التقديم.
| # | الحالة | الخطوات | المتوقع |
|---|---|---|---|
| 7.1 ☐ | تقديم طلب وساطة | تاجر: `/trader/brokerage/new` (وصف، موديل، صور) | مرجع + SUBMITTED؛ رفع الصور يعمل، ملفات سيئة تُرفض |
| 7.2 ☐ | طلب معلومات | الإدارة → NEEDS_INFO مع ملاحظة | التاجر يرى الطلب ويعيد التقديم |
| 7.3 ☐ | الدفع | → AWAITING_PAYMENT ثم «تأكيد الدفع» | → PAYMENT_CONFIRMED |
| 7.4 ☐ | القبول والفحص | ACCEPTED → INSPECTION_SCHEDULED → حفظ نتيجة الفحص → INSPECTED | نتيجة الفحص تُحفظ ويراها التاجر حسب الإعداد |
| 7.5 ☐ | إرسال عرض | INSPECTED → إرسال عرض (QUOTE_SENT) | إشعار للتاجر |
| 7.6 ☐ | رد التاجر | وافق → APPROVED / ارفض → REJECTED | الانتقال الصحيح لكل رد |
| 7.7 ☐ | الشراء والشحن | PURCHASED → SHIPPED → DELIVERED → CLOSED | الحالات تتقدم؛ تخطي حالة يُرفض |
| 7.8 ☐ | الرفض/الإلغاء | DECLINED من الإدارة، CANCELLED من التاجر | الحالات النهائية مغلقة |
| 7.9 ☐ | عزل التجار | تاجر B على طلب A | ممنوع |
